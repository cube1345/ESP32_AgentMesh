# 前端登录系统现状

本文档说明当前 ESPAgent React 前端已经实现的登录系统，以及如果后续要把它升级为真实鉴权系统，ESP32 端或后端还需要补哪些能力。

## 1. 当前已经实现的登录系统

当前前端已经加入一个**本地登录守卫**。

表现形式：

- 未登录时先进入登录页
- 登录成功后才进入 dashboard
- 登录状态会保存在浏览器本地
- 刷新页面后会保留当前会话
- 可以手动退出登录

### 1.1 当前登录页支持的内容

- 用户名输入
- 密码输入
- 登录按钮
- 演示账号提示

### 1.2 当前默认演示账号

当前内置了 3 个本地演示账号：

- `admin / admin123`
- `operator / operator123`
- `viewer / viewer123`

这些账号仅用于前端演示与本地权限区分，不代表真实生产账号体系。

### 1.3 当前登录成功后能做什么

登录后可以使用前端现有全部页面能力：

- 总览面板
- 四节点固定通信面板
- 节点拓扑图
- 环境数据展示
- timeline 展示与筛选
- Skills Studio 草稿编辑
- 用户偏好配置
- AI 通信面板（WebSocket -> ESP32 agent_loop）

## 2. 当前登录系统的边界

当前这套登录系统是：

```text
前端本地登录系统
```

不是：

```text
后端真实鉴权系统
```

### 2.1 当前已经做到

- 前端访问入口保护
- 本地 session 持久化
- 简单角色区分：`admin / operator / viewer`

### 2.2 当前还没有做到

- 服务端账号校验
- JWT / Session Token
- 登录过期时间
- 权限接口鉴权
- ESP32 端用户身份感知
- Guardian 基于登录身份做权限裁决

也就是说，当前登录更多是：

- 防止直接打开页面就进入控制台
- 给演示和后续权限分层预留入口

## 3. 这件事现在需不需要 ESP32 配合

### 3.1 当前这个版本

**不需要 ESP32 配合。**

因为当前登录系统完全在前端本地完成：

- 账号校验在浏览器内
- session 保存在 `localStorage`
- 不会把用户身份下发到 ESP32

所以这版登录系统已经能工作，不依赖板端改动。

### 3.2 如果要升级成真实系统

那就需要后端或 ESP32 配合。

## 4. 如果后续要升级成真实鉴权，需要补什么

如果目标是让登录系统真正影响控制权限，而不是只做前端入口保护，建议补这些内容。

### 4.1 后端鉴权接口

建议新增后端接口，例如：

- `POST /api/login`
- `POST /api/logout`
- `GET /api/me`

用于：

- 校验账号密码
- 返回 token / session
- 获取当前用户信息

### 4.2 前端请求带身份

当前前端请求：

- `/api/dashboard`
- `/api/skills`
- `/api/preferences`

如果启用真实鉴权，后续应带：

- `Authorization` header
- 或 cookie/session

### 4.3 AI 通信面板带用户身份

当前 WebSocket 消息格式只有：

```json
{"type":"message","content":"你好","chat_id":"web_console_01"}
```

如果要让 ESP32 感知用户身份，建议扩展为：

```json
{
  "type": "message",
  "content": "你好",
  "chat_id": "web_console_01",
  "user": {
    "username": "admin",
    "role": "admin"
  }
}
```

这样后续：

- `agent_loop`
- `guardian_agent`
- `policy_check`

都可以按真实用户身份做进一步判断。

### 4.4 Guardian / Policy 与登录身份联动

如果最终要做权限控制闭环，ESP32 侧最好支持：

- 不同用户角色的风险级别映射
- 不同角色可触发的工具白名单
- 高风险操作强制二次确认

例如：

- `viewer`：只允许看，不允许控制
- `operator`：允许普通控制，不允许改 skills
- `admin`：允许高级配置与高风险控制

这一步更适合放在：

- 本地聚合服务
- 或 Guardian / policy_check 侧

## 5. 当前结论

一句话总结：

### 前端现在已经有登录系统

而且：

- 能正常拦截未登录用户
- 能保存本地登录状态
- 能支持多角色演示

### 但这套登录系统现在还是

**前端本地演示级登录**

### 现在不需要 ESP32 配合

因为它还没有进入真实权限控制链路。

### 如果以后要升级成真实控制权限系统

才需要补：

- 后端鉴权
- token/session
- WebSocket 身份传递
- Guardian / policy 联动

## 6. 推荐下一步

如果下一步继续只做前端增强，不动 ESP32，建议：

1. 根据登录角色隐藏部分页面操作
   - `viewer` 只读
   - `operator` 可通信
   - `admin` 可改草稿

2. 在 AI 通信面板里显示当前登录用户

3. 后续再决定是否把用户身份真正下发到 ESP32
